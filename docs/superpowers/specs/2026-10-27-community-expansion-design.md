# 커뮤니티 기능 확장 설계

## 목표
기존 커뮤니티에 중고·구인구직·맛집/여행지 입력 기능, 개인별 차단 콘텐츠 숨김, 새 쪽지 실시간에 가까운 알림을 추가하고 모든 단계를 검증 루프로 진행한다.

## 사용자 목표와 제약
- 사용자는 태국 거주자가 필요한 커뮤니티 정보를 찾고 게시할 수 있다.
- 기존 게시글·댓글·회원 데이터는 보존한다. 기존 카테고리 글은 새 필드 없이 계속 열람되고 수정 가능해야 한다.
- 각 기능은 실패 테스트 작성 → 예상 실패 확인 → 최소 수정 → 관련 회귀·실제 브라우저 확인 → 다음 기능 순서로 구현한다.
- 이 작업에서 운영 배포, 실제 백업 파일의 외부 전송, DB 복원/초기화, 운영 권한 변경은 하지 않는다.
- `/opt/teemo-live-news` 및 별도 뉴스 서비스는 수정하지 않는다.

## 설계
### 게시판 전용 정보
기존 `Post`와 `PostForm` 흐름을 확장하고 정보는 기존 게시글과 같은 DB에 선택형 필드로 저장한다. 모든 신규 필드는 기존 게시물에 nullable/default 값으로 적용해 기존 글을 변환하거나 재작성하지 않는다.

- 중고: 글 종류(판매/구매), 가격(선택; 숫자 0 이상, 통화 표기 명확), 거래 지역, 상태(거래 중/예약/완료). 상태 변경 권한은 작성자 또는 기존 운영자에 한한다.
- 구인구직: 글 종류(구인/구직), 업무 지역, 보상(선택형 문구; 자유 입력을 사용하되 길이 제한), 상태(모집 중/마감). 기존 게시 권한을 유지한다.
- 맛집·여행지: 장소명과 지역, 선택형 방문 메모 및 외부 장소 링크. 입력한 장소명+지역으로 HTTPS Google Maps 검색 URL을 URL 인코딩해 자동 생성한다(`https://www.google.com/maps/search/?api=1&query=...`). 좌표나 검증되지 않은 장소 세부정보를 추측하지 않는다. 외부 링크는 http/https만 허용하고 안전한 새 탭 링크 속성을 사용한다.
- 해당 카테고리가 아닌 기존 카테고리에서는 전용 필드를 숨기고 저장하지 않는다. 목록과 상세에서는 값이 있는 항목만 명확한 레이블로 표시한다.

### 회원 차단 콘텐츠 숨김
`MemberBlock`은 기존 쪽지 차단 관계를 그대로 쓴다. 로그인한 차단자에게만 차단 대상의 게시글·댓글·대댓글 본문을 숨기고, 공개적으로 숨기거나 원본 데이터를 삭제하지 않는다. 글 목록, 상세, 댓글·대댓글, 검색 및 커뮤니티 API에서 같은 규칙을 재사용한다. 상세 직접 URL과 API에서도 적용해 우회 노출을 막는다. 차단 해제 시 원래 게시물이 다시 보인다. 기존 운영자 숨김·복원과의 우선순위는 운영자 숨김 상태를 최우선으로 유지한다. 차단 화면은 작성자명과 본문을 노출하지 않는 자리표시자로 표시한다.

### 쪽지 알림 갱신
기존 서버 렌더링 unread count와 메시지 읽음 상태를 기준으로, 인증된 화면에서 같은 출처의 private/no-store 읽기 전용 카운트 endpoint를 주기적으로 조회한다. 30초 주기로 시작하며 문서가 백그라운드/숨김 상태일 때 요청을 멈추고 다시 활성화될 때 즉시 한 번 조회한다. 사용자의 unread 메시지 수만 반환하며, 익명 요청과 다른 사용자 메시지 접근은 거부한다. 오류 시 기존 표시값을 보존하고 다음 주기에 재시도한다. WebSocket/서버 푸시 인프라와 읽음 처리 정책 변경은 범위에 넣지 않는다.

### 운영 백업 점검
읽기 전용으로 현재 백업의 위치·생성 주기·권한·최근 무결성 및 복구 리허설 근거를 확인하고, 같은 호스트 여부와 외부 보관 공백을 기록한다. 외부 저장소·암호화 키·보존 기간을 임의 선택하거나 회원 DB를 전송하지 않는다. 안전한 외부 보관을 위한 대상과 승인 사항을 보고서로 제시하고 별도 승인 전까지 이동하지 않는다.

## 검증 및 완료 기준
- 각 기능은 TDD로 독립적인 작은 단계마다 검사하고, 구현 뒤에만 다음 단계로 간다.
- 중고/구인/맛집 정보: 유효성, 입력/수정 권한, 잘못된 카테고리 필드 무시/거부, 기존 게시물 마이그레이션 보존, 목록·상세·API·검색의 일관성 검증.
- 지도 링크: 공백·한글/태국어·기호 URL 인코딩, 허용 프로토콜, XSS/`javascript:` 거부 및 실제 브라우저 클릭 확인.
- 차단: 차단자와 비차단자, 익명, 차단 해제, 직접 URL/API, 댓글·대댓글, 운영자 숨김 콘텐츠 경계 테스트. 기존 글·댓글 DB 행은 불변이어야 한다.
- 알림: 수신자 격리, 읽음/미읽음 변경, 인증/익명, cache-control, 30초 지연/탭 숨김 동작, 브라우저의 갱신 및 중복 타이머 없음 확인.
- 320/390/768/1440px 브라우저 반응형, 키보드 접근성, 콘솔 오류 확인. 관련 Django 테스트와 migration check를 실행한다. 기존 브라우저 검사 실패는 변경 전 기준선과 비교해 새 회귀와 분리 기록한다.
- 배포 승인을 구하기 전에 전체 관련 테스트, migration 및 기존 데이터 보존을 확인한다. 이 설계 범위는 운영 배포를 포함하지 않는다.

## 단계와 중단 조건
1. 중고게시판 필드·상태.
2. 구인구직 필드·모집 상태.
3. 맛집/여행 정보와 안전한 지도 검색 링크.
4. 차단 사용자 게시글·댓글 개인별 숨김.
5. 쪽지 읽지 않음 수 주기 갱신.
6. 운영 백업 방식 읽기 전용 점검 보고.

각 단계에서 데이터 손상, 권한 우회, 비공개 정보 노출, 기존 기능 회귀가 생기면 다음 단계로 진행하지 않는다. 외부 데이터 전송이나 운영 변경은 별도 승인 없이는 실행하지 않는다.

## 제외 범위
결제·배송·거래 중개, 채용 지원/이력서 보관, Google Places API/좌표 검증, 실제 WebSocket, DB 운영 배포, 외부 백업 전송, 사이트 뉴스 서비스 수정.
