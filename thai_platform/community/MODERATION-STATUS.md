# 신고·숨김·이의신청: 코드 현황과 결정 사항

문서의 코드 현황은 `harness/moderation` 개발 브랜치에서 확인한 내용이다. 테스트 통과는 로컬 격리 테스트 결과일 뿐, 운영 배포본의 동작을 뜻하지 않는다.

## 구현된 코드

- 신고 사유는 `outdated`, `privacy`, `spam`, `abuse`; 처리 상태는 `open`, `resolved`, `dismissed`다. 신고는 게시글 또는 선택 댓글을 대상으로 한다. `target_type`을 저장해 댓글 삭제 후 신고 대상이 게시글로 오인되지 않게 했다.
- 마이그레이션이 `Report moderators` 그룹을 만든다. 신고 API와 관리자 화면은 활성 `is_staff` 계정 중 이 그룹에 속한 사용자만 이용한다. 슈퍼유저도 그룹 구성원이 아니면 자동 우회하지 않는다.
- 신고 운영자는 열린 신고를 처리하거나 기각할 수 있고, 별도 숨김 동작은 신고된 게시글 또는 댓글만 `hidden` 상태로 바꾼다. 댓글 신고는 부모 게시글을 숨기지 않는다. 대상이 이미 숨겨졌거나 사라진 경우 조치를 거부한다.
- 숨김과 신고 처리 내역은 `AuditEvent`에 기록한다. 신고·이의신청·감사 자료를 만료시키는 작업은 이 기능에 추가하지 않았다. 신고의 게시글 FK는 보호해 게시글 물리 삭제로 신고가 함께 지워지는 것을 막는다. 법률·운영 검토 전 보관기간이나 영구 보관을 확정하지 않는다.
- 숨김 대상 작성자에게 본문이나 신고 상세를 복사하지 않는 알림을 보낸다. 알림에서 이의신청 폼으로 이동할 수 있다. 회원은 자신이 작성한 숨김 게시글 또는 댓글에 대해서만 웹/API로 이의신청을 접수할 수 있다. 이 접수는 자동으로 숨김을 해제하거나 계정 제한을 하지 않는다.
- 일반 직원·슈퍼유저의 게시글 소유권 우회 수정·삭제를 API와 웹 서비스에서 제거했다. 관리자 글·댓글 화면도 읽기 전용이며 숨김은 전용 신고 조치만 사용한다.
- 신고·이의신청 API 응답에는 `Cache-Control: no-store, private`를 설정했다. 이의신청 조회는 작성자 본인 자료로 제한한다.

## 아직 정해지지 않았거나 구현되지 않은 사항

- 이의신청의 심사자 배정, 원 조치 담당자와의 분리, 결과(유지·해제) 처리 및 신청자 통지는 아직 구현하지 않았다. 접수 기록은 신고 운영자 관리자 화면에서 읽을 수 있다.
- 반복 이의신청의 제한·중복 처리, 숨김 해제 절차와 기간은 미정이다.
- 작성자 알림은 숨김 사실과 이의신청 경로만 표시한다. 신고 사유·증거·문의처는 포함하지 않는다. 별도 실제 연락처는 지정하지 않았다.
- 실제 보관 기한, 삭제·익명화 기준, 법률 검토는 남아 있다. 코드에 만료 작업이 없다는 사실은 법적 보관 요건 충족을 보증하지 않는다.

## 검증 경계

격리 개발 환경에서 신고 권한 분리, 댓글만 숨김, 삭제된 대상 보호, 작성자만 이의신청, 개인정보 캐시 제어와 웹 화면 이동을 자동 테스트한다. 운영 데이터베이스·배포본·실제 운영자 그룹 설정은 이 작업에서 확인하거나 변경하지 않는다. 배포와 운영 권한 부여는 별도 승인과 운영 검증이 필요하다.
